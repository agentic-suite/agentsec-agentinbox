# PRD 11 — Decisions (the frozen design choices)

**BLUF:** The ten decisions that make agentinbox safe, small, and embeddable — each stated as a rule, the
alternatives rejected, and the reason. These are the PRD-level commitments; lower-level mechanisms (hash
construction, token format, schema DDL) are ADR material under `docs/adr/`.

**Status:** Draft — v0.1.0 (2026-11-04) · **Owner:** @deghosal-2026 · **Parent:** agentic-suite #209 · PRD #220

| # | Decision (the rule) | Alternatives considered | Why this one |
|---|---|---|---|
| **D-1** | **Timeout = deny. Always.** No config flips it to allow or pause. | pause-the-session; extendable TTL; allow-after-N-warnings | The PRD's open question is *resolved for v0.1.0* in the safe direction: a gate nobody answers must fail closed. Pause semantics differ per harness (a headless agent cannot pause), so "deny + rescope hint" is the only portable safe outcome. Design partners may revisit *pause for interactive* in v0.1.x as an **additive, opt-in** behavior, never a default. |
| **D-2** | **Approval binds to the action identity** (`tool`+`action`+canonical args), single-use, expiring with the ask. | approve-the-scope (tool/class-level approval); durable approvals; id-only binding | Class-level approvals are standing policy (R10, v1.x), not an approval — conflating them is how "yes once" becomes "yes forever". agentpolicy's `action_identity` + `deny_action_identity_mismatch` already implement the binding; we reuse, not reinvent. |
| **D-3** | **An answer = a valid claim + an authenticated principal, both.** Never a client-supplied `approver` string; never token-only. | trust-the-channel (Slack says the user clicked); trust-the-token (possession = authorization) | A forwarded message carries the token but not the person; a stolen session carries the person but not the binding. Both checks make each channel's weakness irrelevant. |
| **D-4** | **The ask record is the approval object** — one durable row (plus transitions) is the source of truth, like a ServiceNow approval record, not like a chat message. | derive approvals from channel events; separate decision objects from asks | Reconstruction, export, and cross-channel consistency all fall out of one object with a state machine; channel events are *observations* of it, never the record itself. |
| **D-5** | **Channels are renderers, not deciders.** Slack renders the card and authenticates the click; terminal renders and reads a keypress; CI waits. All three funnel into the same answer-verifier. | per-channel approval logic; smart channel adapters | Per-channel logic forks the security review and guarantees drift (the exact bug class that makes "approved in Slack" ≠ "approved in terminal"). |
| **D-6** | **The ask contract is open and SDK-agnostic** (`ask/1.0` JSON over HTTP + CLI). agentpolicy is the first producer, never the only interface. | SDK-first coupling to agentpolicy; MCP-only surface; per-harness formats | The harness-compatibility mandate requires that any harness can emit an ask; a JSON contract is the only surface all harnesses can call (frameworks have no common SDK, but they all have processes). |
| **D-7** | **Terminal-first, then desktop + webhook, then CI, then Matrix — chat platforms (Slack/Teams) optional.** A working zero-chat, zero-cloud path ships before any external dependency. | Slack-first (reach); broker-first (queue-native); CI-first (enterprise) | Terminal proves the lifecycle with nothing to integrate; desktop + webhook prove reach without a platform; CI proves headless; Matrix proves remote-interactive + spoof resistance on an **open** protocol. The product must be complete for users who run no chat platform at all ([PRD 16 §A.2](16-channel-and-harness-adapters.md)). Zero-cloud mode is permanent, not a fallback (CUJ-12). |
| **D-8** | **Local-first single store, single principal at v0.1.0; server mode later reuses the same core.** | server-first (enterprise appeal); distributed/queued architecture | A local-first tool is installable, testable, air-gappable, and honest. Enterprise identity needs are real but a fake RBAC is worse than documented absence. SQLite/WAL handles the actual load (TTL-bounded pending sets). |
| **D-9** | **No ML anywhere in the decision path. No free-text approval surface in v0.** | natural-language approvals ("approve with caveat: only staging"); LLM triage of asks | The anti-requirement from the consolidated PRD is a security property: an approval is a cryptographic event, not a sentence a model interpreted. Free text is where spoofability and ambiguity enter; structured actions are auditable and unambiguous. |
| **D-10** | **agentwatch is the only event vocabulary we emit into**; the local audit chain is the evidence of record. | bespoke event format; SIEM-native formats only | One vocabulary across the ecosystem means a session's trace and its gates join without adapters (R5). OCSF mapping rides agentwatch's existing mapping. |
| **D-11** | **Escalation changes routing, never the deadline.** Each tier re-issues claims and invalidates superseded ones. | extending TTL per escalation ("give the next tier a fair window") | The TTL is the security property; escalation-with-extension is a denial-of-decision waiting to happen (an attacker who can suppress acks gets infinite extension). The last tier sees the remaining time. |
| **D-12** | **Flood denial is a decision, not a suppression.** Throttled asks resolve deny with `ask_flood_throttled` and the producer learns it. | queue and replay asks post-flood; silently drop | A looping agent must *stop*, not wait; silence teaches it nothing and queues become unbounded. Deny + one event + one digest is safe for the approver and informative for the agent. |
| **D-13** | **The queue moves; the store decides.** Delivery/escalation/digest jobs ride a pluggable **bus** (in-proc, filesystem spool, later Redis/NATS); authoritative state — asks, claims, the audit chain — lives only in a pluggable **store** (SQLite, later Postgres/embedded). Jobs are at-least-once; consumers are idempotent by ask state. | queue-as-truth (asks live in the broker); store-as-bus (poll the DB); stateless tokens everywhere | A message that says "approved" and a record that says "pending" is the classic approval-system corruption; redeliverable movement plus a transactional, gapless-seq store is the only shape where replay is harmless and evidence holds. Both are conformance-gated contracts (E11/E12), so drivers are replaceable without re-deriving semantics. |
| **D-14** | **Filesystem bus before brokers; one box, honestly.** The v0.1.0 bus is the filesystem spool (atomic tmp→rename, fsync, `flock`, inotify/poll) and it is explicitly single-machine; multi-machine is the Redis/NATS drivers' job in server mode. | Redis-first (cloud-native default); pretending a directory is distributed | OSS users trust what they can `tail -f`; a spool is inspectable, dependency-free, and durable by default. The single-writer limit is enforced loudly (`flock` refusal), not discovered at 3 a.m. ([PRD 16 §A.2](16-channel-and-harness-adapters.md)). |
| **D-15** | **Approve the effect; bind both identities.** Approvals bind to the human-readable effect fingerprint *and* the machine identity (`action_identity`) — and an effect without a provable containment renders **unverified**. | tool-call-only binding (brittle across harness renames); effect-only binding (spoofable prose) | Humans reason about effects; machines enforce identities. Requiring both closes the harness-drift hole *and* the prose-spoofing hole at once ([PRD 24 R13](24-constrained-approvals-and-effects.md)). |
| **D-16** | **The inbox records constraints; the enforcer enforces them.** No constraint may be offered that the producer's enforcement path cannot honor; a constraint is a binding the policy layer names in its deny when exceeded. | inbox-side sandboxing; advisory-only constraints | An advisory constraint is a security lie — the first `max_rows=100` ask that runs 101 is the end of the product's credibility. The PDP/PEP split stays intact ([PRD 24 §enforcement-honesty](24-constrained-approvals-and-effects.md)). |
| **D-17** | **Precedent and history are display, never input.** No similar-ask history, hit count, or "last time approved" can answer, auto-answer, or alter the binding of an ask — advisory rendering only. | history-weighted auto-approval (fatigue relief) | The moment history can approve, an attacker who can shape history can approve. Fatigue is fought with grouping, constraints, and standing rules *with expiry* — never with silent precedent ([PRD 26 R36](26-approver-experience-operations.md)). |
| **D-18** | **Staleness degrades to re-confirm; it never silently extends or releases.** A changed freshness basis blocks the bare answer and demands an explicit re-confirm of the new basis — the clock keeps running the whole time. | auto-revalidate and proceed; TTL reset on drift | Long-lived approvals drifting over changed context is how "yes" stops meaning anything; and a drift that *extends* the TTL is an escalation bypass wearing a freshness costume ([PRD 24 R16](24-constrained-approvals-and-effects.md)). |
| **D-19** | **`needs_changes` is a real outcome with a running clock.** The review loop never pauses or extends a TTL: hold-and-clarify lives inside the remaining window, resolve-and-reask mints a new ask on a shared thread. | pause-on-request-changes; auto-extend for clarifications | Every "just one more second" extension is an escalation bypass with a polite name; the deadline is the security property, and feedback is delivered *inside* it ([PRD 28 R48](28-review-loops-and-orchestration.md), E15). |
| **D-20** | **Every convenience grant is scoped, expiring, and audited — session grants and suppressions die on their own.** No grant, window, or suppression outlives its declared ceiling, and none applies outside its declared scope. | rolling re-grants; broad incident-wide suppression; suppression of irreversible classes by default | "Stop asking me" is the exact sentence that precedes every standing-privilege incident; the safe version is a 30-min scalpel, not a permanent switch ([PRD 28 R51–R53](28-review-loops-and-orchestration.md)). |
| **D-21** | **Attestations describe facts, never judgments — and never authorize anything.** A signed attestation proves who decided, what, when, with what provenance and evidence digests; it does not claim the decision was *right*, and it can never release an action. | attesting "approved correctly"; attestation-as-token | Evidence that flatters becomes marketing; evidence that authorizes becomes a forged-approval primitive. The auditor's artifact must be useless to an attacker ([PRD 29 R63/E16](29-trust-maturity-writeback-performance.md)). |
| **D-22** | **Writeback is post-decision, best-effort, and never authoritative.** GitHub checks, PR comments, and ticket updates happen *after* the record is final; a dead token is an event, never a block, and the local chain remains the only truth. | writeback-before-commit; remote state as the record | If outbound state could gate or block, a third-party outage would become a fail-open/fail-closed coin flip we don't control. The store decides; the world gets told ([PRD 29 R64](29-trust-maturity-writeback-performance.md)). |
| **D-23** | **Conflict resolution is a fixed lattice, not an engine.** Deny-shapes outrank allow-shapes; human answers outrank convenience rules but lose to freshness, provenance, window, and dependency failures; ties resolve restrictively. No user-programmable weights. | configurable priority scores; "most recent wins" | Every precedence-engine product ends up with both bugs and marketing; a shipped, tested total order is auditable prose ([PRD 30 R68](30-correctness-conflict-abuse-hardening.md)). |
| **D-24** | **States move forward only; the graph is versioned; terminal is terminal.** The only backward edges are the bounded review-loop returns and stale→re-confirmed, each capped by hard limits. | reopen/resurrect flows; mutable terminal states | A resurrected approval is a forged approval with extra steps; the fuzz fixture makes every illegal edge a logged rejection ([PRD 30 R69](30-correctness-conflict-abuse-hardening.md)). |
| **D-25** | **All outbound side effects are idempotent by key, and "recorded" ≠ "delivered."** Each writeback/hook/check carries an idempotency key; retries are safe no-ops; the two truths are stored separately and both replayable. | at-most-once with manual reconciliation | Distributed reality delivers duplicates; a side-effect system that can double-fire a PR comment can double-fire a release ([PRD 30 E17](30-correctness-conflict-abuse-hardening.md)). |
| **D-26** | **Edits are monotonic-narrowing by default; broadening is a declared, tier-gated exception.** Widening scope (recipients up, staging→prod, dry-run off) is rejected unless the class explicitly allows it — and then only at the class's maximum provenance tier, rendered loudly. | free-form editing by any approver | The edit feature is only safe if the envelope is mathematical, not social; "the approver seemed careful" is not a control ([PRD 30 R71](30-correctness-conflict-abuse-hardening.md)). |
| **D-27** | **No advisory allows.** If the producer/enforcer cannot prove it enforced the returned outcome, the fallback is deny or re-ask — every shaped outcome (constraint, edit, window, grant) included. | "allow with a warning" for unenforceable constraints | An unenforced constraint is worse than a deny: it launders the risk through a human's "yes" ([PRD 30 R73](30-correctness-conflict-abuse-hardening.md)). |
